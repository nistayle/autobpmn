# AutoBPMN - Release v1.1.0 (Performance & Event-Loop Optimization)
**Tanggal Rilis:** 16 Oktober 2026  
**Status:** Latest Release  

---

## Ringkasan Rilis
Rilis v1.1.0 berfokus pada **stabilitas pemrosesan, eliminasi hang/freeze, perbaikan async event-loop, serta pembersihan dependensi frontend**.

---

## Rincian Perubahan & Perbaikan Bug

### 1. Fix Event Loop Starvation di FastAPI (`backend/app/api/v1/pipeline.py`)
* **Masalah**: Fungsi ekstraksi LLM (`extract_sop_to_graph`) bersifat synchronous dan melakukan blocking I/O jaringan. Ketika dipanggil langsung di dalam fungsi route async, event loop FastAPI terhenti (*freeze*). Akibatnya request `/health` maupun request ekstraksi lainnya hang tanpa batas waktu dan tombol browser stuck di status **"Mengekstrak..."**.
* **Solusi**: Membungkus eksekusi fungsi ekstraksi menggunakan `await asyncio.to_thread(extract_sop_to_graph, payload.text_content)`. Ekstraksi kini berjalan aman di threadpool latar belakang tanpa menghalangi event loop utama server.

### 2. Smart Provider Prioritization & Fail-Fast Key Validation (`backend/app/services/extractor.py`)
* **Masalah**: Kunci Gemini di `.env` yang tidak berformat resmi (`AIzaSy...`) menyebabkan sistem mencoba menghubungi Google API berulang kali sebelum beralih ke provider lain.
* **Solusi**:
  - Menambahkan validasi awal format kunci Gemini (`api_key.startswith("AIzaSy")`).
  - Jika kunci Gemini tidak valid, sistem **secara otomatis langsung memprioritaskan Groq (`gsk_...`) dan OpenRouter (`sk-or-...`)** di urutan terdepan.
  - Membatasi pencarian model kandidat Gemini hingga maksimal 4 model prioritas.

### 3. Responsiveness & Timeout Tuning
* **Masalah**: Timeout bawaan `urllib.request` disetel hingga 120 detik per model, membuat pengguna menunggu terlalu lama saat terjadi network lag atau rate limit.
* **Solusi**:
  - Menurunkan timeout request per model menjadi **25 detik**.
  - Menambahkan logging real-time di terminal backend (`[AutoBPMN] Menghubungi <provider> model: <model>...`) sehingga progres eksekusi terpantau secara transparan.

### 4. Pembersihan Dependensi Frontend (`frontend/package.json` & `frontend/vite.config.js`)
* **Masalah**: Error build `hero-ui` / `@tailwindcss/vite` yang tidak kompatibel mengganggu dev server.
* **Solusi**: Menghapus paket yang tidak digunakan (`@heroui/react`, `@tailwindcss/vite`, `tailwindcss`, `framer-motion`), merampingkan konfigurasi `vite.config.js` menjadi Vite + React murni, serta mengonfirmasi kelancaran hot-module reload (HMR).
